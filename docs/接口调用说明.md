# 洪水灾害情景态势与物资需求开放 API 调用说明

本文档面向接口调用方，说明如何完成认证、组织请求、理解枚举字段以及处理返回结果。接口地址和 API Key 由平台提供方分配。

## 1. 接口概览

| 序号 | 功能 | 方法 | 路径 |
| --- | --- | --- | --- |
| 1 | 新增灾害事件 | `POST` | `/openapi/v1/disaster-events` |
| 2 | 更新灾害事件 | `PUT` | `/openapi/v1/disaster-events/{eventId}` |
| 3 | 为事件追加灾情观测 | `POST` | `/openapi/v1/disaster-events/{eventId}/observations` |
| 4 | 按区域和时间查询灾害事件 | `GET` | `/openapi/v1/disaster-events` |
| 5 | 导入事件并计算区域情景态势 | `POST` | `/openapi/v1/region-situation-assessments` |
| 6 | 查询区域历史情景态势 | `GET` | `/openapi/v1/region-situation-assessments` |
| 7 | 直接计算物资需求 | `POST` | `/openapi/v1/material-demand-calculations` |
| 8 | 根据已保存的区域态势计算物资需求 | `POST` | `/openapi/v1/material-demand-calculations/from-region-data` |

调用地址由“环境基础地址 + 接口路径”组成。例如本地联调环境：

```text
基础地址：http://localhost:18080
完整地址：http://localhost:18080/openapi/v1/disaster-events
```

## 2. 请求认证和公共请求头

### 2.1 请求头说明

| 请求头 | 是否必填 | 适用接口 | 填写说明 |
| --- | --- | --- | --- |
| `X-API-Key` | 是 | 全部接口 | 填写平台提供方分配的完整 API Key，例如 `flood_live_xxxxxxxx.xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx`。不要添加 `Bearer`，也不要填写成 `X-API-Key: ...` 以外的形式。 |
| `Idempotency-Key` | 写入和计算接口必填 | 所有 `POST`、`PUT` 接口 | 调用方为本次业务操作生成的唯一值，长度为 1～128 个字符。建议使用“系统名 + 操作名 + 业务编号”或 UUID。 |
| `X-Request-Id` | 否 | 全部接口 | 调用方生成的请求追踪编号。允许字母、数字、点、下划线、冒号和短横线，长度 1～64 个字符。省略时平台会生成。最终采用的编号会通过响应头 `X-Request-Id` 返回。 |
| `Content-Type` | 有 JSON 请求体时必填 | 所有 `POST`、`PUT` 接口 | 固定填写 `application/json`。 |
| `Accept` | 否 | 全部接口 | 建议填写 `application/json`。错误响应的格式为 `application/problem+json`。 |

标准请求头示例：

```http
X-API-Key: flood_live_xxxxxxxx.xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
Idempotency-Key: caller-a-event-create-20260824-0001
X-Request-Id: caller-a-20260824-0001
Content-Type: application/json
Accept: application/json
```

### 2.2 API Key 使用要求

- API Key 由平台提供方发放，调用方不能自行编造。
- 在 Swagger 的 **Authorize** 窗口中，只粘贴完整 API Key，不要输入 `X-API-Key:`，也不要添加 `Bearer`。
- API Key 可能具有接口权限、有效期、调用频率或来源地址限制。返回 `403 INSUFFICIENT_SCOPE` 时，应联系平台提供方开通对应权限。
- 不要把 API Key 放在 URL、请求体、日志、截图或公开代码仓库中。
- API Key 失效、过期、格式错误或不符合调用限制时，返回 `401 INVALID_API_KEY`。

各接口所需权限如下：

| 接口功能 | 所需权限 |
| --- | --- |
| 新增、更新事件，追加观测 | `event:write` |
| 查询事件 | `event:read` |
| 计算区域情景态势 | `situation:calculate` |
| 查询历史情景态势 | `situation:read` |
| 两种物资需求计算 | `material:calculate` |

### 2.3 Idempotency-Key 使用要求

`Idempotency-Key` 用于避免调用超时或网络重试造成重复数据。

- 第一次提交一个写入或计算请求时生成一个新值。
- 请求超时、连接中断或未收到明确结果时，重试同一请求必须继续使用原值，并保持路径、参数和请求体不变。
- 新的业务操作或请求内容发生变化时，必须更换新的值。
- 同一个 `Idempotency-Key` 对应不同请求内容时，返回 `409 IDEMPOTENCY_CONFLICT`。
- `GET` 查询接口不需要填写该请求头。

## 3. 公共调用规则

### 3.1 时间格式

所有请求时间均使用 ISO 8601 格式，并且必须显式携带北京时间偏移 `+08:00`。

正确示例：

```text
2026-08-24T09:30:00+08:00
2026-08-24T09:30:00.123+08:00
```

错误示例：

```text
2026-08-24T09:30:00Z          不允许使用 UTC 的 Z
2026-08-24T09:30:00           缺少 +08:00
2026-08-24T09:30:00+09:00     不是北京时间偏移
```

事件时间、观测时间和态势评估时间最多保留到毫秒，即小数点后最多 3 位。

### 3.2 行政区域填写

区域对象格式如下：

```json
{
  "regionId": "320111",
  "regionName": "浦口区"
}
```

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| `regionId` | 与 `regionName` 至少填写一个 | 六位行政区划编号，推荐优先填写，例如 `320111`。 |
| `regionName` | 与 `regionId` 至少填写一个 | 行政区域名称。只填写名称时，该名称必须能唯一确定一个区域。 |

建议始终使用 `regionId`。如果两个字段同时填写，它们必须指向同一个区域，否则返回 `409 REGION_SELECTOR_MISMATCH`。只填名称且存在重名区域时返回 `409 REGION_NAME_AMBIGUOUS`。

### 3.3 分页格式

事件查询和态势查询使用相同的分页参数：

| 参数 | 是否必填 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `page` | 否 | `0` | 页码，从 0 开始。 |
| `size` | 否 | `20` | 每页数量，范围为 1～100。 |

分页响应格式：

```json
{
  "items": [],
  "page": 0,
  "size": 20,
  "totalElements": 0,
  "totalPages": 0
}
```

## 4. 枚举字段完整说明

枚举值区分大小写，必须按照下表中的英文值填写。

### 4.1 灾害事件类型 `eventType`

| 枚举值 | 中文含义 | 适用说明 |
| --- | --- | --- |
| `RIVER_FLOOD` | 河流洪水 | 河道、江河水位上涨或漫溢导致的洪水。 |
| `URBAN_WATERLOGGING` | 城市内涝 | 城镇排水不畅、道路或居民区积水。 |
| `FLASH_FLOOD` | 山洪 | 山区短时间强降雨引发的突发洪水。 |
| `EMBANKMENT_BREACH` | 堤防决口 | 江河、湖泊堤防发生决口。 |
| `DAM_BREAK` | 水库或大坝溃决 | 水库、大坝等挡水设施发生溃决。 |
| `OTHER` | 其他洪水相关事件 | 无法归入以上类型的洪水灾害。 |

### 4.2 灾害事件状态 `status`

| 枚举值 | 中文含义 | `endTime` 要求 | 是否参与指定时刻的态势聚合 |
| --- | --- | --- | --- |
| `ONGOING` | 持续中 | 必须不传或填写 `null` | 当 `startTime` 和观测时间均不晚于评估时刻时参与。 |
| `ENDED` | 已结束 | 必填，并且不得早于 `startTime` | 不参与当前态势聚合，但事件仍会保存。 |
| `CANCELLED` | 已取消 | 可不填；填写时不得早于 `startTime` | 不参与当前态势聚合，但事件仍会保存。 |

常见错误组合：

```json
{
  "status": "ONGOING",
  "endTime": "2026-08-24T12:00:00+08:00"
}
```

以上组合无效，因为持续中的事件不能填写结束时间。

### 4.3 区域情景态势等级 `situationLevel`

| 枚举值 | 中文含义 |
| --- | --- |
| `LOW` | 低态势等级 |
| `MEDIUM` | 中态势等级 |
| `HIGH` | 高态势等级 |

### 4.4 物资计算人口基数 `populationBasis`

该字段只出现在物资计算响应中，用于说明某项物资按哪类人口计算。

| 枚举值 | 中文含义 |
| --- | --- |
| `AFFECTED` | 按受影响人数计算 |
| `TRAPPED` | 按受困人数计算 |
| `EVACUATED` | 按已转移或疏散人数计算 |
| `VULNERABLE` | 按脆弱人群人数计算 |
| `FIXED` | 按固定数量计算，不以人口为基数 |

### 4.5 物资计算数据来源 `sourceType`

| 返回值 | 中文含义 |
| --- | --- |
| `DIRECT` | 调用方直接提供态势等级和人口数据。 |
| `DATABASE` | 使用指定时间区间内最新的一条已保存区域态势数据。 |

## 5. 公共灾情观测对象

观测对象用于“新增事件的首条观测”“追加事件观测”和“区域态势计算中的事件观测”。

```json
{
  "externalObservationId": "OBS-EXT-001",
  "observedAt": "2026-08-24T10:00:00+08:00",
  "hazard": {
    "rainfall24hMm": 200,
    "waterLevelOverWarningM": 0.8,
    "maxWaterDepthM": 1.2,
    "affectedAreaKm2": 15.5
  },
  "impact": {
    "affectedPopulation": 30000,
    "trappedPopulation": 2000,
    "evacuatedPopulation": 100,
    "vulnerablePopulation": 500,
    "injuredPopulation": 10,
    "missingPopulation": 0,
    "deathPopulation": 0,
    "damagedHouseholds": 200,
    "collapsedHouses": 5,
    "roadInterruptions": 8,
    "criticalFacilitiesAffected": 2,
    "powerOutageHouseholds": 1000
  }
}
```

### 5.1 观测基本字段

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| `externalObservationId` | 否 | 调用方系统中的观测编号，建议填写并在同一事件内保持唯一。 |
| `observedAt` | 是 | 观测时间，必须使用 `+08:00`，不得早于事件开始时间。 |
| `hazard` | 否 | 灾害强度指标。整个对象可省略，未知的单个指标也可填 `null` 或省略。 |
| `impact` | 是 | 受灾影响指标。人数和数量均不得小于 0。 |

### 5.2 灾害强度 `hazard`

| 字段 | 单位 | 说明 |
| --- | --- | --- |
| `rainfall24hMm` | 毫米 | 24 小时累计降雨量，必须大于或等于 0。 |
| `waterLevelOverWarningM` | 米 | 超过警戒水位的高度，必须大于或等于 0。 |
| `maxWaterDepthM` | 米 | 最大积水或淹没深度，必须大于或等于 0。 |
| `affectedAreaKm2` | 平方千米 | 受影响面积，必须大于或等于 0。 |

### 5.3 受灾影响 `impact`

| 字段 | 含义 |
| --- | --- |
| `affectedPopulation` | 受影响总人数。 |
| `trappedPopulation` | 受困人数，不得超过 `affectedPopulation`。 |
| `evacuatedPopulation` | 已转移或疏散人数，不得超过 `affectedPopulation`。 |
| `vulnerablePopulation` | 需要重点保障的脆弱人群数，不得超过 `affectedPopulation`。 |
| `injuredPopulation` | 受伤人数。 |
| `missingPopulation` | 失踪人数。 |
| `deathPopulation` | 死亡人数。 |
| `damagedHouseholds` | 受损户数。 |
| `collapsedHouses` | 倒塌房屋数。 |
| `roadInterruptions` | 中断道路数量。 |
| `criticalFacilitiesAffected` | 受影响的重要设施数量。 |
| `powerOutageHouseholds` | 停电户数。 |

所有字段必须是大于或等于 0 的整数。没有数据时建议显式填写 `0`，避免调用双方对缺省值产生不同理解。

## 6. 灾害事件接口

### 6.1 新增灾害事件

```http
POST /openapi/v1/disaster-events
```

必需请求头：`X-API-Key`、`Idempotency-Key`、`Content-Type: application/json`。

请求字段：

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| `externalEventId` | 是 | 调用方系统中的事件编号，与 `sourceSystem` 组合后应唯一。 |
| `sourceSystem` | 是 | 调用方来源系统标识，例如 `EMERGENCY_PLATFORM`。 |
| `region` | 是 | 事件所属区域，参见“行政区域填写”。 |
| `eventType` | 是 | 灾害事件类型，参见 `eventType` 枚举。 |
| `eventName` | 是 | 便于识别的事件名称。 |
| `startTime` | 是 | 事件开始时间。 |
| `endTime` | 条件必填 | 根据 `status` 填写。 |
| `status` | 是 | 事件状态，参见 `status` 枚举。 |
| `initialObservation` | 否 | 首条灾情观测，格式参见“公共灾情观测对象”。 |

请求示例：

```json
{
  "externalEventId": "EXT-FLOOD-20260824-001",
  "sourceSystem": "EMERGENCY_PLATFORM",
  "region": {
    "regionId": "320111"
  },
  "eventType": "RIVER_FLOOD",
  "eventName": "浦口区河流洪水",
  "startTime": "2026-08-24T08:00:00+08:00",
  "endTime": null,
  "status": "ONGOING",
  "initialObservation": {
    "externalObservationId": "OBS-EXT-001",
    "observedAt": "2026-08-24T09:00:00+08:00",
    "hazard": {
      "rainfall24hMm": 180,
      "maxWaterDepthM": 1.2
    },
    "impact": {
      "affectedPopulation": 1500,
      "trappedPopulation": 100,
      "evacuatedPopulation": 300,
      "vulnerablePopulation": 120,
      "injuredPopulation": 5,
      "missingPopulation": 0,
      "deathPopulation": 0,
      "damagedHouseholds": 20,
      "collapsedHouses": 0,
      "roadInterruptions": 2,
      "criticalFacilitiesAffected": 1,
      "powerOutageHouseholds": 50
    }
  }
}
```

成功状态码为 `201`。响应中的 `eventId` 是平台事件编号，后续更新事件或追加观测必须使用该值，而不是 `externalEventId`。

```json
{
  "eventId": "EVT_01m0hp1as75c71rfyb11py43ra",
  "externalEventId": "EXT-FLOOD-20260824-001",
  "sourceSystem": "EMERGENCY_PLATFORM",
  "region": {
    "regionId": "320111",
    "regionName": "浦口区"
  },
  "eventType": "RIVER_FLOOD",
  "eventName": "浦口区河流洪水",
  "startTime": "2026-08-24T08:00:00+08:00",
  "endTime": null,
  "status": "ONGOING",
  "observationId": "OBS_01m0hp2pr87ykx6mxkkm1wm1vc",
  "createdAt": "2026-08-24T09:01:00+08:00",
  "updatedAt": "2026-08-24T09:01:00+08:00"
}
```

### 6.2 更新灾害事件

```http
PUT /openapi/v1/disaster-events/{eventId}
```

`eventId` 必须使用新增或查询接口返回的、以 `EVT_` 开头的平台事件编号。

该接口是完整更新，不是局部更新。每次都必须提交 `eventType`、`eventName`、`startTime` 和 `status`，并根据状态决定是否填写 `endTime`。事件的来源编号、来源系统和所属区域不能通过本接口修改。

结束事件示例：

```json
{
  "eventType": "RIVER_FLOOD",
  "eventName": "浦口区河流洪水",
  "startTime": "2026-08-24T08:00:00+08:00",
  "endTime": "2026-08-24T18:00:00+08:00",
  "status": "ENDED"
}
```

成功状态码为 `200`，响应格式与新增事件响应一致。

### 6.3 追加灾情观测

```http
POST /openapi/v1/disaster-events/{eventId}/observations
```

请求体使用“公共灾情观测对象”。`observedAt` 不得早于该事件的 `startTime`。

成功状态码为 `201`：

```json
{
  "observationId": "OBS_01m0hp2pr87ykx6mxkkm1wm1vc",
  "observedAt": "2026-08-24T10:00:00+08:00",
  "hazard": {
    "rainfall24hMm": 205,
    "waterLevelOverWarningM": 0.8,
    "maxWaterDepthM": 1.5,
    "affectedAreaKm2": 15.5
  },
  "impact": {
    "affectedPopulation": 1800,
    "trappedPopulation": 120,
    "evacuatedPopulation": 350,
    "vulnerablePopulation": 150,
    "injuredPopulation": 5,
    "missingPopulation": 0,
    "deathPopulation": 0,
    "damagedHouseholds": 25,
    "collapsedHouses": 0,
    "roadInterruptions": 3,
    "criticalFacilitiesAffected": 1,
    "powerOutageHouseholds": 70
  }
}
```

### 6.4 查询灾害事件

```http
GET /openapi/v1/disaster-events
```

查询参数：

| 参数 | 是否必填 | 说明 |
| --- | --- | --- |
| `regionId` | 与 `regionName` 至少一个 | 行政区域编号。 |
| `regionName` | 与 `regionId` 至少一个 | 行政区域名称。 |
| `startTime` | 是 | 查询窗口开始时间。 |
| `endTime` | 是 | 查询窗口结束时间，必须晚于 `startTime`。 |
| `status` | 否 | `ONGOING`、`ENDED` 或 `CANCELLED`。 |
| `page` | 否 | 从 0 开始，默认 0。 |
| `size` | 否 | 1～100，默认 20。 |

该接口返回与查询时间窗口有交集的事件，不仅限于在窗口内开始的事件。

调用示例：

```http
GET /openapi/v1/disaster-events?regionId=320111&startTime=2026-08-24T00%3A00%3A00%2B08%3A00&endTime=2026-08-25T00%3A00%3A00%2B08%3A00&status=ONGOING&page=0&size=20
X-API-Key: flood_live_xxxxxxxx.xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

返回的每个事件包含最新一条观测 `latestObservation`；没有观测时该字段为 `null`。结果按事件开始时间倒序返回。

## 7. 区域情景态势接口

### 7.1 导入事件并计算区域情景态势

```http
POST /openapi/v1/region-situation-assessments
```

请求字段：

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| `region` | 是 | 本次评估的行政区域。所有 `events` 都应属于该区域。 |
| `assessmentTime` | 是 | 评估时刻，使用北京时间。 |
| `events` | 是 | 当前掌握的灾害事件数组，至少 1 条。传入的事件及观测也会成为后续查询可用的数据。 |

`events` 中每个事件的字段：

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| `externalEventId` | 是 | 调用方系统中的事件编号。 |
| `sourceSystem` | 是 | 来源系统标识。 |
| `eventType` | 是 | 参见 `eventType` 枚举。 |
| `eventName` | 是 | 事件名称。 |
| `startTime` | 是 | 事件开始时间。 |
| `endTime` | 条件必填 | 根据事件状态填写。 |
| `status` | 是 | 参见 `status` 枚举。 |
| `observation` | 是 | 本次评估使用的灾情观测。观测时间不得早于事件开始时间，也不得晚于 `assessmentTime`。 |

请求示例：

```json
{
  "region": {
    "regionId": "320111"
  },
  "assessmentTime": "2026-08-24T12:00:00+08:00",
  "events": [
    {
      "externalEventId": "EXT-ASSESS-001",
      "sourceSystem": "EMERGENCY_PLATFORM",
      "eventType": "RIVER_FLOOD",
      "eventName": "浦口区河流洪水",
      "startTime": "2026-08-24T08:00:00+08:00",
      "endTime": null,
      "status": "ONGOING",
      "observation": {
        "externalObservationId": "OBS-ASSESS-001",
        "observedAt": "2026-08-24T12:00:00+08:00",
        "hazard": {
          "rainfall24hMm": 200,
          "maxWaterDepthM": 1.5
        },
        "impact": {
          "affectedPopulation": 1500,
          "trappedPopulation": 100,
          "evacuatedPopulation": 300,
          "vulnerablePopulation": 120,
          "injuredPopulation": 5,
          "missingPopulation": 0,
          "deathPopulation": 0,
          "damagedHouseholds": 20,
          "collapsedHouses": 0,
          "roadInterruptions": 2,
          "criticalFacilitiesAffected": 1,
          "powerOutageHouseholds": 50
        }
      }
    }
  ]
}
```

只有满足以下条件的事件参与本次区域态势聚合：

- `status` 为 `ONGOING`；
- `startTime` 不晚于 `assessmentTime`；
- `observation.observedAt` 不晚于 `assessmentTime`。

其他传入事件仍会保存，但不计入本次 `activeEventCount` 和聚合人口。

成功状态码为 `201`。主要响应字段：

| 字段 | 说明 |
| --- | --- |
| `assessmentId` | 平台生成的态势评估编号，以 `RSA_` 开头。 |
| `region` | 评估区域。 |
| `assessmentTime` | 评估时刻。 |
| `situationLevel` | 区域态势等级：`LOW`、`MEDIUM` 或 `HIGH`。 |
| `activeEventCount` | 实际参与聚合的持续中事件数量。 |
| `aggregateImpact` | 参与聚合事件的人口合计。 |
| `eventResults` | 每个参与聚合事件的评估结果。 |
| `importSummary` | 本次事件和观测的新增、更新、重复情况。 |
| `ruleVersion` | 本次评估采用的业务规则版本。 |
| `warnings` | 数据使用提示。没有提示时为空数组。 |
| `createdAt` | 结果生成时间。 |

当多个事件均包含人口数据时，响应可能包含：

```json
{
  "code": "POSSIBLE_POPULATION_OVERLAP",
  "message": "MVP 未使用 GIS，跨事件人口可能存在重复统计"
}
```

调用方应将该提示展示给业务人员，避免把聚合人口直接理解为已去重人数。

### 7.2 查询区域历史情景态势

```http
GET /openapi/v1/region-situation-assessments
```

查询参数：

| 参数 | 是否必填 | 说明 |
| --- | --- | --- |
| `regionId` | 与 `regionName` 至少一个 | 行政区域编号。 |
| `regionName` | 与 `regionId` 至少一个 | 行政区域名称。 |
| `startTime` | 是 | 查询窗口开始时间，包含该时刻。 |
| `endTime` | 是 | 查询窗口结束时间，不包含该时刻，且必须晚于 `startTime`。 |
| `situationLevel` | 否 | `LOW`、`MEDIUM` 或 `HIGH`。 |
| `page` | 否 | 从 0 开始，默认 0。 |
| `size` | 否 | 1～100，默认 20。 |

结果按评估时间倒序返回，响应采用公共分页格式。

## 8. 物资需求计算接口

物资编码、名称、单位和计算标准由平台提供方配置，不属于固定枚举。调用方填写当前库存前，应先确认平台当前使用的物资编码及对应单位。

### 8.1 直接计算物资需求

```http
POST /openapi/v1/material-demand-calculations
```

请求字段：

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| `region` | 是 | 物资需求对应的行政区域。 |
| `situationLevel` | 是 | `LOW`、`MEDIUM` 或 `HIGH`。 |
| `supplyDurationHours` | 是 | 计划保障时长，单位小时，必须大于 0，最多 3 位小数。不足 24 小时按 1 天计算。 |
| `reserveRatio` | 否 | 额外储备比例，范围 0～1，最多 6 位小数。例如 `0.10` 表示 10%。省略时采用当前物资标准中的比例。 |
| `population` | 是 | 本次计算使用的受灾人口数据。 |
| `currentInventory` | 否 | 当前库存数组；无库存或不抵扣库存时传 `[]` 或省略。 |

`population` 字段：

| 字段 | 说明 |
| --- | --- |
| `affectedPopulation` | 受影响总人数。 |
| `trappedPopulation` | 受困人数。 |
| `evacuatedPopulation` | 已转移或疏散人数。 |
| `vulnerablePopulation` | 需要重点保障的脆弱人群数。 |

以上人口数均为大于或等于 0 的整数。

`currentInventory` 中每项字段：

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| `materialCode` | 是 | 平台物资标准中的物资编码。数组内不能重复。 |
| `quantity` | 是 | 当前可用库存，必须大于或等于 0，最多 4 位小数。 |
| `unit` | 是 | 必须与该物资在当前标准中的单位完全一致，包括大小写。 |

请求示例：

```json
{
  "region": {
    "regionId": "320111"
  },
  "situationLevel": "HIGH",
  "supplyDurationHours": 72,
  "reserveRatio": 0.10,
  "population": {
    "affectedPopulation": 1500,
    "trappedPopulation": 100,
    "evacuatedPopulation": 300,
    "vulnerablePopulation": 120
  },
  "currentInventory": [
    {
      "materialCode": "DRINKING_WATER",
      "quantity": 500,
      "unit": "L"
    }
  ]
}
```

### 8.2 根据已保存的区域态势计算物资需求

```http
POST /openapi/v1/material-demand-calculations/from-region-data
```

该接口不需要调用方填写态势等级和人口数据。平台会使用指定区域、指定时间区间内最新的一条已保存态势及其聚合人口进行计算。

请求字段：

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| `region` | 是 | 要查询态势并计算物资需求的区域。 |
| `assessmentTimeRange` | 是 | 已保存态势的查询时间范围。 |
| `supplyDurationHours` | 是 | 计划保障时长，单位小时，必须大于 0，最多 3 位小数。 |
| `currentInventory` | 否 | 当前库存数组，规则与直接计算接口一致。 |

请求示例：

```json
{
  "region": {
    "regionId": "320111"
  },
  "assessmentTimeRange": {
    "startTime": "2026-08-24T00:00:00+08:00",
    "endTime": "2026-08-25T00:00:00+08:00"
  },
  "supplyDurationHours": 72,
  "currentInventory": []
}
```

时间范围包含 `startTime`，不包含 `endTime`。范围内没有已保存态势时返回 `422 NO_SITUATION_DATA`。

### 8.3 物资计算响应

两个物资接口成功状态码均为 `201`，响应格式相同：

```json
{
  "calculationId": "MDC_01m0hqf1f8b9b7y4y1j7dcb2fb",
  "sourceType": "DIRECT",
  "assessmentId": null,
  "region": {
    "regionId": "320111",
    "regionName": "浦口区"
  },
  "situationLevel": "HIGH",
  "supplyDurationHours": 72.000,
  "supplyDays": 3,
  "items": [
    {
      "materialCode": "DRINKING_WATER",
      "materialName": "饮用水",
      "populationBasis": "AFFECTED",
      "basisPopulation": 1500,
      "grossDemand": 25992.0000,
      "currentInventory": 500.0000,
      "netDemand": 25492.0000,
      "unit": "L"
    }
  ],
  "standardVersion": "material-standard-v1.0",
  "warnings": [],
  "createdAt": "2026-08-24T12:01:00+08:00"
}
```

主要响应字段：

| 字段 | 说明 |
| --- | --- |
| `calculationId` | 本次物资计算编号，以 `MDC_` 开头。 |
| `sourceType` | `DIRECT` 或 `DATABASE`。 |
| `assessmentId` | 使用已保存态势时为对应 `RSA_` 编号；直接计算时为 `null`。 |
| `supplyDays` | 保障天数，按 `supplyDurationHours / 24` 向上取整。 |
| `items` | 各项物资计算结果。 |
| `grossDemand` | 库存抵扣前的需求量。 |
| `currentInventory` | 本次参与抵扣的库存量。 |
| `netDemand` | 库存抵扣后的最终需求量，最低为 0。 |
| `standardVersion` | 本次采用的物资标准版本。 |

文档示例中的物资项目和数量仅用于说明响应格式，正式结果以接口实际返回及业务方确认的物资标准为准。

## 9. 错误响应

调用失败时，响应体格式如下：

```json
{
  "requestId": "req_01m0hr2vdv9r3xg8m51xq6gkze",
  "errorCode": "VALIDATION_ERROR",
  "message": "Request validation failed",
  "details": [
    {
      "field": "eventName",
      "message": "must not be blank"
    }
  ],
  "timestamp": "2026-08-24T12:05:00+08:00"
}
```

| HTTP 状态码 | `errorCode` | 调用方处理建议 |
| --- | --- | --- |
| 400 | `MALFORMED_REQUEST` | 检查 JSON 格式、必填查询参数和枚举拼写。 |
| 401 | `INVALID_API_KEY` | 检查是否填写完整 API Key；仍失败时联系平台提供方确认有效期和调用限制。 |
| 403 | `INSUFFICIENT_SCOPE` | 当前 API Key 没有该接口权限，联系平台提供方授权。 |
| 404 | `REGION_NOT_FOUND` | 检查地区编号或名称。 |
| 404 | `EVENT_NOT_FOUND` | 检查是否使用正确的 `EVT_` 事件编号。 |
| 409 | `REGION_NAME_AMBIGUOUS` | 区域名称不唯一，改用 `regionId`。 |
| 409 | `REGION_SELECTOR_MISMATCH` | `regionId` 与 `regionName` 指向不同区域。 |
| 409 | `EVENT_CONFLICT` | 同一来源事件编号已存在，但固定信息不同；核对来源、区域、类型和开始时间。 |
| 409 | `OBSERVATION_CONFLICT` | 同一观测标识已存在，但观测内容不同。 |
| 409 | `IDEMPOTENCY_CONFLICT` | 同一 `Idempotency-Key` 被用于不同请求，更换 Key 或恢复原请求内容。 |
| 422 | `VALIDATION_ERROR` | 根据 `message` 和 `details` 修正字段值、时间、状态或人口关系。 |
| 422 | `INVALID_TIME_RANGE` | 确保开始时间严格早于结束时间。 |
| 422 | `REGION_EVENT_MISMATCH` | 检查事件是否属于本次请求区域。 |
| 422 | `NO_ACTIVE_RULE_SET` | 当前评估时间没有可用态势规则，联系平台提供方。 |
| 422 | `NO_SITUATION_DATA` | 指定区域和时间范围内没有已保存态势；先调用态势计算接口或调整时间范围。 |
| 422 | `NO_ACTIVE_MATERIAL_STANDARD` | 当前没有可用物资标准，联系平台提供方。 |
| 422 | `NO_MATERIAL_STANDARD_ITEM` | 当前条件没有匹配的物资项目，联系平台提供方确认区域和态势等级。 |
| 422 | `UNIT_MISMATCH` | 库存单位与物资标准单位不一致，使用平台提供的标准单位。 |
| 429 | `RATE_LIMIT_EXCEEDED` | 调用频率过高，稍后重试；持续发生时联系平台提供方。 |
| 500 | `INTERNAL_ERROR` | 保留响应中的 `requestId`，联系平台提供方排查。 |

出现问题时，请向平台提供方提供以下信息：

- 请求时间；
- 请求方法和路径；
- 响应状态码；
- 响应体中的 `requestId` 和 `errorCode`；
- 已脱敏的请求参数。

不要在问题记录、邮件或聊天工具中发送完整 API Key。

## 10. Swagger 和 Postman 调用提示

### 10.1 Swagger

本地联调地址：

```text
http://localhost:18080/swagger-ui.html
```

使用步骤：

1. 点击页面右上角 **Authorize**。
2. 在 `ApiKeyAuth` 的 Value 中粘贴完整 API Key。
3. 点击 **Authorize**，然后关闭弹窗。
4. 打开要测试的接口，点击 **Try it out**。
5. 对于 `POST`、`PUT` 接口，在 `Idempotency-Key` 中填写本次操作的唯一值。
6. `X-Request-Id` 可以留空，也可以填写调用方自己的追踪编号。
7. 填写参数和请求体后点击 **Execute**。

### 10.2 Postman

在请求的 **Headers** 中添加：

```text
X-API-Key        平台提供的完整 API Key
Idempotency-Key  写入或计算请求的唯一操作编号；GET 请求不填
X-Request-Id     可选追踪编号
Content-Type     application/json
```

在 **Body** 中选择 **raw** 和 **JSON**，再粘贴对应接口的请求示例。查询接口的参数填写在 **Params** 中；时间值建议直接填写完整的 `+08:00` 字符串，由 Postman 完成 URL 编码。
